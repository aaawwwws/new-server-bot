# new-server-bot

TypeScript + discord.js で作った Discord Bot。

## セットアップ

```sh
npm install
cp .env.example .env   # Windows (PowerShell): Copy-Item .env.example .env
```

`.env` に以下を設定する。

| 項目 | 内容 |
| --- | --- |
| `DISCORD_TOKEN` | Bot のトークン。[Discord Developer Portal](https://discord.com/developers/applications) の対象アプリ > **Bot** > **Reset Token** で取得 |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | DB のユーザー名・パスワード・DB名（パスワードは長いランダムな文字列にする） |
| `DATABASE_URL` | PC 上の `npm run dev` から DB への接続先。上の3つと同じ値で `postgres://ユーザー:パスワード@localhost:5432/DB名` |

## 起動

Bot と PostgreSQL は Docker で動かす。

```sh
docker compose up -d --build   # Bot と DB をビルドしてバックグラウンドで起動（Docker が起動すると自動で立ち上がる）
docker compose logs -f bot     # Bot のログを見る（Ctrl+C で抜ける。Botは止まらない）
docker compose down            # 停止（DBのデータは残る）
```

コードを変更したら `docker compose up -d --build` で作り直す。

### 開発するとき（PC 上で Bot を動かす）

```sh
docker compose stop bot        # Docker の Bot を止める（同じBotが2つ動くと二重に反応してしまう）
docker compose up -d db        # DB だけ起動
npm run dev                    # ファイル変更で自動再起動
```

## データベース

登録されたプロフィールは PostgreSQL の `profiles` テーブルに保存される（1サーバーにつき1人1件）。
ほかに、申請（`profile_applications`）、メンバーごとの設定（`member_settings`）、レベル（`member_levels`・日ごとの `level_daily_xp`）、ランキング掲示板（`ranking_boards`）、週・月の結果（`ranking_results`・`ranking_periods`）、XPアップ期間（`xp_boosts`）、パーティ募集（`recruits`・作りかけ `recruit_drafts`・テンプレート `recruit_templates`・一覧 `recruit_lists`）、設置したパネルの場所（`panels`）、
行動ログ（`activity_logs`）・発言（`message_logs`・30日で消す）・VCの出入り（`voice_sessions`）も保存する。テーブルは Bot の起動時に自動で作られる。

- データは Docker のボリューム `db-data` に残るので、`docker compose down` やPCの再起動では消えない
- `docker compose down -v` はボリュームごと消すので **データも全部消える**
- 中身を見る: `docker compose exec db psql -U bot -d bot -c "SELECT * FROM profiles"`
- DB は `127.0.0.1:5432` にだけ公開しているので、同じPCからしか接続できない

## Bot をサーバーに招待

以下の URL の `<アプリID>` を Developer Portal の **General Information** > **Application ID** に置き換えて開く。

```
https://discord.com/oauth2/authorize?client_id=<アプリID>&scope=bot+applications.commands&permissions=268520454
```

付与される権限: ロールの管理 / チャンネルを見る / メッセージを送信 / 埋め込みリンク / メッセージ履歴を読む / メンバーをキック / メンバーをBAN

## コマンド

コマンドは `/メンバー検索`・`/レベル`・`/ランキング` を除き、**「管理者」ロールを持つメンバーだけ** が使える（ほかの人が使うと本人にだけ断りが出る）。
ロールを作る前でも困らないよう、サーバーのオーナーは常に使える。パネルのボタンは誰でも押せる。

「管理者」ロールは、Bot の起動時（と新しいサーバーに招待されたとき）になければ自動で作り、Bot のロールのすぐ下に置く。
Discord の権限は何も付けないので、必要なら サーバー設定 > ロール で設定する。作ったあとは、管理する人にロールを付けること。

コマンド自体はメンバー全員の一覧に表示される。一般メンバーに見せたくない場合は、
サーバー設定 > 連携サービス > このBot から、コマンドを使えるロールを「管理者」だけにする。

### `/進行度パネル`（英語クライアントでは `/progress-panel`）

実行したチャンネルに、拡張ごとの進行度ロールを選べるボタン付きパネルを設置する。

- 実行時、`src/expansions.ts` の拡張名と同じ名前のロールがなければ自動で作成する（あれば既存のものを使う）
- メンバーがボタンを押すと、そのロールが付く。進行度ロールは1人1つで、別のボタンを押すと付け替わる
- パネル設置後はロールIDで紐付いているので、ロール名や色を変えても動く

**注意:** サーバー設定 > ロール で、Bot のロールを進行度ロールより **上** に置くこと。
下にあると権限不足でロールを付けられない。

新しい拡張が出たら `src/expansions.ts` に追記して `/進行度パネル` を一度実行する（足りないロールが作られる）。
増えた新しいパネルは消してよい。設置済みのパネルは、次の Bot の起動時にロールに合わせて作り直される（[パネルの自動更新](#パネルの自動更新)）。

### `/コンテンツパネル`（英語クライアントでは `/content-panel`）

実行したチャンネルに、よく遊ぶコンテンツのロールを選べるパネルを設置する。

- ロール: レイド / ギャザクラ / SS / ハウジング / PvP / 地図 / 特殊フィールド / ルレ（`src/contentRoles.ts` で変更できる）
- 押すとロールが付き、もう一度押すと外れる。いくつでも付けられる。押した人にだけ、今のコンテンツロールが表示される
- 設置時、同じ名前のロールがなければ自動で作る（名前の色が変わらないよう、色は付けない）
- 付け外しは「ログ」に残る
- プロフィールに「🎮 よく遊ぶ」として表示される。登録済みの人が付け外しすると、`プロフ` の投稿もすぐ更新される
- 「⚙️ 設定」→「🪪 プロフィール」→「🎮 コンテンツ」からも付け外しできる

### `/プロフィールパネル`（英語クライアントでは `/profile-panel`）

実行したチャンネルに「プロフィールを作成」ボタンを設置する。
先に次のものを作っておくこと（足りないとパネル設置時に警告が出る）。

| 名前 | 種類 | 用途 |
| --- | --- | --- |
| `プロフ` | テキストチャンネル | 許可されたプロフィールが投稿される |
| `確認` | テキストチャンネル（管理者だけ見える） | 申請が届き、許可・拒否する |
| `正規メンバー` | ロール（Bot のロールより下に置く） | 申請が許可されたメンバーに付く |

ボタンを押したメンバーは、本人にだけ見えるメッセージで順番に入力していく。

1. モーダルで 名前・苗字・ひとこと を入力
   （FF14 のルールで確認する: 半角英字と ' - のみ、それぞれ2〜15文字、合わせて20文字以内。先頭は自動で大文字）
2. 進行度を選択（押すとすぐロールが付いて次へ進む）
3. データセンター → そのDCのワールド を選択
4. 活動時間（開始・終了）を選択
5. 使用するジョブを選択（1つ以上必須・複数可）
6. よく遊ぶコンテンツを選択（任意・いくつでも。押すとすぐロールが付く）
7. VC通知を受け取るかを選択（「受け取る」「受け取らない」のどちらかを選ぶまで「申請する」は押せない）して「申請する」
   （すでに「VC」ロールが付いている人は「受け取る」が選ばれた状態から始まる）

- 進行度・コンテンツ・「VC」のロールがないサーバーでは、その手順を飛ばす（最後の手順に「申請する」が出る）

- 各ステップでプレビューが表示される
- 登録済みの人がもう一度ボタンを押すと、前回の内容が入った状態で変更して申請し直せる
- 進行度と「よく遊ぶ」はロールから載る。あとで進行度パネル・コンテンツパネル・設定パネルでロールを変えると、`プロフ` の投稿もすぐ更新される
- 進行度・コンテンツ・VC通知は押した時点でロールが付け外しされる（申請の審査を待たない）

#### 申請の審査

「申請する」を押すと、`確認` チャンネルに申請が届く（プロフに載るのと同じ埋め込み付き）。

| ボタン | 動き |
| --- | --- |
| ✅ 許可する | `プロフ` に投稿（登録済みなら上書き）・DB に保存・`正規メンバー` を付ける。申請者に DM で知らせる |
| ❌ 拒否する | 理由を入力（任意）して拒否。申請者に理由付きで DM を送る |
| 👤 メンバーを見る | 申請者の Discord プロフィールを開く |
| 👢 キック | 理由を入力（任意）してサーバーからキック。先に申請者へ DM を送る。理由は監査ログにも残る |
| 🔨 BAN | 理由を入力（任意）して BAN。申請者がもうサーバーにいなくても BAN できる |

- キック・BAN は「管理者」ロールの人だけが押せる。理由の入力画面で「送信」するまで実行されない
- 申請者が Bot より上のロールを持っているなど、キック・BAN できない場合は、押した人に知らせて審査中のまま残す
- どれかを処理すると申請メッセージに「✅ @管理者 が許可しました」のように結果が残り、ボタンはすべて消える
- 複数の管理者が同時に押しても、処理されるのは1回だけ（後の人には「すでに処理されています」と出る）
- 審査中にもう一度申請されると、古い申請は「新しい申請が届いたため無効」になる
- 申請者が DM を受け付けていない場合は、申請メッセージに「DMを送れませんでした」と残る
- 申請者がサーバーを抜けていて投稿できないときは、審査中のまま残る（あとで許可・拒否できる）
- 申請の履歴は DB の `profile_applications` テーブルに残る
- データセンターとワールドは `src/dataCenters.ts`、ジョブは `src/jobs.ts` で変更できる

### `/設定パネル`（英語クライアントでは `/settings-panel`）

実行したチャンネルに「⚙️ 設定」パネルを設置する。ボタンは誰でも押せる。

「🪪 プロフィール」を押すと、本人にだけ見える画面に今のプロフィールと次の項目が出る（登録済みの人だけ）。
項目を押すと同じ画面がその変更画面に切り替わり、変更後は「ほかの項目も変更する」で一覧に戻れる。

| 項目 | 変更できること |
| --- | --- |
| 🪪 名前・ひとこと | キャラクター名（FF14 のルールで確認）とひとこと |
| 📖 進行度 | 進行度ロール（押すとすぐ付け替わる） |
| 🌍 ワールド | データセンター → ワールド |
| 🕘 活動時間 | 開始・終了を選んで「保存」 |
| ⚔️ ジョブ | 付け外しして「保存」（1つ以上必須） |
| 🎮 コンテンツ | コンテンツロール（押すとすぐ付け外し・いくつでも） |

- 審査なしで、すぐ `プロフ` の投稿と DB に反映する。変更したことは「ログ」に変更前と変更後付きで残る
- 未登録の人には「先にプロフィールパネルから申請してください」と出る
- 管理者が「正規メンバー」ロールを外した人が変更しても、ロールは付け直さない
- 審査中の申請がある人が変更しても、その申請をあとで許可すると申請の内容で上書きされる

「🔔 VC通知」を押すと、本人にだけ見える画面で次の3つを切り替えられる（今の設定は青く表示される）。

| 設定 | ボタン | 動き |
| --- | --- | --- |
| ① 通知を受け取る | 受け取る / 受け取らない | 誰かが通話を始めたときの @VC のメンション（[通話の開始・終了のお知らせ](#通話の開始終了のお知らせ)）。「VC」ロールの付け外し |
| ② 自分が通話を始めたとき | 通話開始を知らせる / 知らせない | 知らせないにすると、自分が始めた通話の開始のお知らせが @VC なし・通知なしで流れる |
| ③ 自分がVCに入ったとき | プロフィールを出す / 出さない | 出さないにすると、[VC入室のお知らせ](#vc入室のお知らせ) を自分の分だけ送らない |

- ②③ は最初はどちらも「する」（これまでどおり）。DB の `member_settings` テーブルに保存する
- プロフィールとは関係ないので、未登録の人も使える。切り替えたことは「ログ」に 🔔 で残る

### `/管理パネル`（英語クライアントでは `/admin-panel`）

実行したチャンネルに、管理者用の操作パネルを設置する（管理者用のチャンネルに置くのがおすすめ）。
パネルのボタンも「管理者」ロールの人だけが使える。

| ボタン | 動き |
| --- | --- |
| 👤 ユーザーを登録 | メンバーを選んで（名前で検索できる。IDの入力は不要）、本人の登録と同じ手順（キャラクター名・ひとこと → 進行度 → DC → ワールド → 活動時間 → ジョブ → コンテンツ → VC通知）で入力し、最後の「登録する」で審査なしで `プロフ` に投稿・DB に保存・`正規メンバー` を付ける |

- 入力中の画面の一番上に「👤 @〇〇 のプロフィールを登録しています（管理者）」と出る。進行度ロールは選んだメンバーに付く
- 登録済みのメンバーを選ぶと、今の内容（ジョブなど）が入った状態から始まる。ひとことを空欄にすると今の内容のまま
- 入力中のボタンには登録するメンバーが記録されているので、Bot を再起動しても別の人と取り違えない。「管理者」ロールの人しか押せない
- 登録したことは「ログ」に残る

### `/募集パネル`・`/募集一覧`（英語クライアントでは `/recruit-panel`・`/recruit-list`）

`/募集パネル` を実行したチャンネルに「📣 パーティ募集」パネルを設置する（募集専用のチャンネルに置くのがおすすめ）。
募集はこのチャンネルに投稿され、パネルは埋もれないようにいつも一番下に置き直す。
`/募集一覧` を実行したチャンネルには、募集中のパーティの一覧を置く（募集が変わると自動で書き換わる。1サーバーに1つ）。

募集を作る・参加するのは「正規メンバー」ロールの人と管理者だけ（そのロールがないサーバーでは誰でも）。

#### 募集を作る（ボタンで順番に選ぶ）

「📣 募集を作成」→ タイトル・コメントを入力したあと、1画面ずつ選んでいく（画面の上に、今の内容がまとめて出る）。

| 手順 | 選ぶもの |
| --- | --- |
| 1. 募集の形 | フルパーティ（MT/ST/H1/H2/D1〜D4）・ライトパーティ（T/H/D1/D2）・人数だけ（2〜8人・24人、ロール不問）。**ジョブ重複なし / あり**（なしなら同じジョブは1人まで） |
| 2. DC | Elemental / Gaia / Mana / Meteor / 指定しない（最初は自分のプロフィールのDC） |
| 3〜5. 開始日時 | 日付（今日から7日分）→ 時（18〜23時のボタンか、0〜23時のメニュー）→ 分（10分ごと）。「今すぐ始める」もある。日本時間で、60日先まで |
| 6. 主催の参加 | 主催が入る枠（2つ以上選ぶと FLEX）と、使うジョブ（いくつでも）。「主催は参加しない」も選べる |
| 7. 枠の設定 | 枠ごとに **ジョブ指定**（このジョブの人だけ）、**サーバーの人で埋める**・**外部の人で埋める**（事前埋まり）、**〆**（ゲーム内募集で埋まった）、空きに戻す |
| 8. メンション | 投稿するときにメンションするロール（5つまで・任意。例: レイド） |
| 9. 確認 | 投稿される形のプレビュー。ここから各手順に戻って直せる。**テンプレートに保存** もできる |

- 投稿すると、参加者の **連絡用スレッド** を作る（参加した人は自動で追加される）
- 作りかけの内容は DB に残る（24時間）。Bot を再起動しても、「募集を作成」→「作りかけの続きから」で再開できる
- **テンプレート**: 保存しておくと、「募集を作成」でテンプレートを選ぶだけで、内容・形・DC・ジョブ指定・時刻・メンションが入った状態から始まる（日付だけ毎回選ぶ）。1サーバー25個まで。消せるのは作った人と管理者

#### 参加する

- 「✋ 参加する」→ 入ってよい枠（いくつでも）と、使えるジョブ（いくつでも・選ばなければ未定）を選んで「この内容で参加」
  - **枠を2つ以上選ぶと FLEX**。空いている方に自動で入り、あとから来た人のために自動で入れ替わることもある（例: D1/D2 FLEX の人は、D1 しか選べない人が来たら D2 に移る）
  - ジョブを2つ以上選ぶと、ジョブ指定・ジョブ重複に合わせて自動で決まる
  - 「コメントを付けて参加」で一言（「初見です」など）を付けられる
- 割り振りは、条件（枠のロール・ジョブ指定・ジョブ重複・事前埋まり・〆）を全部満たすように毎回まとめて決め直す。**先に参加した人（と主催が入れた人）が優先** で、新しく来た人のせいで前からいる人が外れることはない（入れなければ、理由を出して断る）
- 「📋 参加メニュー」: 参加内容を変える・コメント・参加を取り消す
- 主催が枠の設定を変えたなどで入れる枠がなくなった人は **補欠** になり、枠が空くと自動で入る（入ったら知らせる）

#### お知らせ（連絡用スレッドに出す）

- 参加・取り消し・FLEX での移動、全員そろったとき（🎉）、開始時刻が変わったとき、開始10分前（⏰、まだ空いている人数も）、中止
- 開始から3時間たつと自動で【終了】になり、ボタンを消してスレッドを閉じる

#### 主催メニュー（募集した人と管理者だけ）

| ボタン | 動き |
| --- | --- |
| ✏️ 内容・ルール | タイトル・コメント・DC・ジョブ重複（なしにして重なった人は補欠になり、本人に知らせる） |
| 🕘 開始時刻 | 日付 → 時 → 分 で選び直す、30分・1時間遅らせる、今すぐ。参加者に知らせる |
| 🧩 枠の設定 | 作るときと同じ（ジョブ指定・事前埋まり・〆）。そのせいで入れなくなった人は補欠になり、本人に知らせる |
| 👑 主催を譲る | メンバーを選んで主催を変える（前の主催は主催メニューを使えなくなる） |
| 🚫 締め切る / 🔓 募集を再開 | 新しく参加できなくする / 戻す（参加している人は、締め切ったあとも変更・取り消しができる） |
| 👋 参加者を外す | 選んだ人を外す |
| 🗑️ 中止する | 確認のあと【中止】にして参加者に知らせ、スレッドを閉じる |

- 操作のたびに **↩️ 元に戻す** が出る（10分間）。そのあとに誰かが参加・変更していたら、今の内容を壊さないよう元に戻さない
- 作成・中止・主催の変更は「ログ」に残る。募集は DB の `recruits` テーブルに残るので、Bot を再起動しても続きから使える

#### 参考にした Bot から変えたところ

- 作りかけの内容を Bot の中だけでなく DB に残すので、再起動で消えない
- FLEX の割り振りを「特別な枠」の場合分けではなく、全員の希望をまとめて満たす方法で毎回決め直す（ジョブ指定・重複禁止・事前埋まり・〆と組み合わせても崩れない）
- 新しく参加した人のせいで、前からいる人が外れない
- 元に戻すとき、そのあとの変更を上書きしない
- 時刻はいつも日本時間で扱う（Bot が動くサーバーの時刻設定に左右されない）

### `/メンバー検索`（英語クライアントでは `/member-search`）

**誰でも使える**（ほかのコマンドは管理者だけ）。条件に合うメンバーのプロフィールを探し、結果は自分にだけ表示する。

- 条件: ジョブ / ロール（タンク・ヒーラー・DPS）/ データセンター / ワールド / 進行度 / コンテンツ / 時刻（その時刻に遊んでいる人。22〜2時のような日またぎも見る）
- 条件は組み合わせられる。何も指定しないと登録している全員
- 結果は20人まで表示し、プロフの投稿へのリンクが付く

### レベル（設定パネルの「📊 レベル」、`/レベル`・`/ランキング`）

**誰でも使える**（プロフィール未登録の人も）。結果は自分にだけ表示する。

- 設定パネルの「📊 レベル」: 自分のレベル（画像カード付き）が出る。下のメニューでほかの人を選ぶとその人のレベルに切り替わる。ボタンで「🏆 ランキング」「🙋 自分の順位」「🏛️ 歴代記録」へ。自分の画面には「🙈 ランキングに出さない」の切り替えも出る
- 同じものをコマンドでも見られる
  - `/レベル`（英語クライアントでは `/level`）: 画像カード（アイコン・名前・順位・レベル・次のレベルまでのゲージ）と、順位・累計XP・連続日数・発言数・VCの時間・今週のXP・リアクションの回数。「メンバー」を選ぶとほかの人のも見られる
  - `/ランキング`（英語クライアントでは `/ranking`）: ランキングの画面を開く。「種類」と「期間」を選べる（指定しないと XP の今週）
- 画像カードは `@napi-rs/canvas` で描く。Docker では日本語・絵文字のフォント（Noto）を入れてある。描けなかったときは文字のゲージで表示する

#### ランキングの画面

| | 内容 |
| --- | --- |
| 種類 | ✨ XP / 💬 発言数 / 🎧 VCの時間 / 💖 もらったリアクション / 🔥 連続日数 / 📣 募集の主催 / 🙋 募集の参加 |
| 期間 | 今日・今週（月曜から）・今月・累計（連続日数は期間なし） |
| ページ | 10人ずつ。「◀️ 前へ」「▶️ 次へ」「📍 自分の位置へ」 |

- 自分が今のページにいないときは「あなたの周り」（1つ上と1つ下の人）を出す。一番下に自分の順位と「○位まであと ○○」
- XP・発言数・VC・もらったリアクションの今週・今月・累計は、昨日の時点からの順位の変化を ⬆2 ⬇1 🆕（昨日はいなかった人）で出す
- 連続日数: 発言・VC・リアクションをした日が何日続いているか（リアクションをもらっただけの日は数えない）。今日まだ来ていなくても、昨日まで続いていれば途切れていない扱い。最長記録も出す
- 募集の主催・参加: 終わった募集だけを数える（中止は数えない。参加は枠に入っていた人だけで、待ちは数えない）
- 「🙋 自分の順位」: 今日・今週・今月・累計それぞれの XP・発言数・VC・もらったリアクションの順位と、連続日数、募集の主催・参加の順位をまとめて出す
- 「🏛️ 歴代記録」: 歴代の週間1位・月間MVP、週間1位の回数、自分の自己ベスト（週間・月間の最高順位、1週間・1日の最高XP、最長の連続日数）
- 順位はサーバーにいる人だけで数える（抜けた人の記録は残すが、順位には入れない）
- 「管理者」ロールの人はランキングに入らない（掲示板・週間/月間の結果・ロールも同じ）。XP は貯まり、レベルの画面の順位は「対象外」になる。本人の「自分の順位」には、入った場合の順位が出る

#### ランキングに出さない設定

- 本人が「🙈 ランキングに出さない」を選ぶと、すべてのランキング・掲示板・週間/月間の結果に名前が出なくなり、ロールも付かない。XP は貯まり続ける
- 本人の「自分の順位」には、出した場合の順位が出る。ほかの人がその人のレベルを見ても、順位は「非表示」になる
- DB の `member_settings` テーブルに保存し、切り替えたことはログに残す

#### 経験値（XP）の貯まり方（数字は `src/levels.ts` で変えられる）

| | もらえるXP | 条件 |
| --- | --- | --- |
| 💬 発言 | 1回 15〜25（ランダム） | 連投で増えすぎないよう、1人1分に1回まで（発言の数はすべて数える）。Bot・Webhook は除く |
| 🎧 VC | 1分ごとに 5 | 2人以上いるVCで、ミュート・スピーカーミュートしていない人（ミュート中の人も人数には数える）。AFKチャンネル・Botは除く |
| 📺 配信 | 1分ごとに 3 を上乗せ（合わせて 8） | VCで配信（画面共有）している人。配信中はミュートしていてもVCのXPがもらえる（カメラは対象外） |
| 👍 リアクションをした | 1回 3（XPになるのは1日10回まで） | 同じメッセージへは、絵文字を変えても・付け直しても1回だけ。外しても減らない |
| 💖 リアクションをもらった | 1人から1回 5（XPになるのは1日20回まで） | 同じ人から同じメッセージへは1回だけ。自分の投稿へのリアクション、Botのリアクション、Bot・Webhook の投稿へのリアクションは数えない |

- XPアップ期間中は、ここに倍率がかかる（下の「XPアップ」）
- 次のレベルまでに要るXPは `5×レベル² + 50×レベル + 100`（Lv1 まで 100、Lv10 まで合計 4,675）
- レベルアップのお知らせは出さない。レベルに応じたロールも付けない
- 記録は DB の `member_levels`（合計）と `level_daily_xp`（日ごとの XP・発言数・VCの時間・リアクションの回数）に残る。XPにしたリアクションは `reaction_xp` に90日残す（同じメッセージへの2回目を数えないため）。期間ごとの発言数・VCは、この機能を入れた日から数える。発言の連投の判定は Bot の中だけで覚えているので、再起動すると最初の1回はすぐXPになる

#### XPアップ（管理パネルの「⚡ XPアップ」）

- 管理者が倍率（1.5倍・2倍・3倍）・開始（空欄なら今すぐ。「10/31 20:00」の形で予約もできる。60日先まで）・長さ（1時間〜1週間）・名前を決めて設定する
- 開催中・予定のものは一覧に出て、「止める」で止められる（開催中なら今で終わり、予定なら取り消し）。重なっているときは倍率の大きい方
- 開催中・次の予定は、ランキング掲示板・レベル・ランキングの画面に出る。設定・停止はログに残る

### `/ランキング掲示板`（英語クライアントでは `/ranking-board`）

実行したチャンネルに、経験値ランキングの掲示板を設置する（1サーバーに1つ。設置し直すと前の掲示板は消える）。

- 掲示板: 「📅 今日」「🗓️ 今週（月曜から）」「🌙 今月」の上位10人（今週・今月は昨日からの変化付き）と、「👑 先週の上位」3人・「🌟 先月のMVP」。5分ごとに、変わったときだけ書き換える
- 掲示板のボタン: 「🙋 自分の順位を見る」「🏆 ランキングを詳しく見る」「🏛️ 歴代記録」（押した人にだけ表示）
- 毎週月曜0時（日本時間）に「🏆 先週の経験値ランキング」を投稿し、1〜3位に「週間ランキング上位」ロールを付ける。毎月1日0時に「🌟 先月の経験値ランキング」を投稿し、1位に「月間MVP」ロールを付ける（ロールはなければ作る。前に付いていた人からは外す）
- Bot が止まっていて月曜0時・1日0時を過ぎたときは、動き出したときに投稿する（同じ期間を二重には投稿しない）
- 週・月が終わると、上位10人を歴代記録として DB（`ranking_results`）に残す。こちらは掲示板がなくても残す
- 数えるのは、その期間に貯まった経験値（発言・VC）。順位はサーバーにいる人だけで数える。掲示板のメッセージを消すと更新は止まる（設置し直せばまた動く）

### 管理パネルのそのほかのボタン

| ボタン | 動き |
| --- | --- |
| 📋 審査中の申請 | まだ許可・拒否していない申請の一覧（申請へのリンク付き） |
| 👥 未登録のメンバー | 入ったまま、プロフィールを登録していない人の一覧（参加が古い順。申請中の人には 📝） |
| 🔎 ログ検索 | 残しておいた行動ログ・発言・VCの出入りを、メンバー・種類・期間・キーワードで探す。一覧か CSV（[ログ検索](#ログ検索)） |
| ⚡ XPアップ | 期間を決めて XP を1.5〜3倍にする。予約・停止もできる（[XPアップ](#xpアップ管理パネルのxpアップ)） |
| 🗑️ プロフィールを削除 | メンバーを選んで、プロフィールと `プロフ` の投稿を削除する。「正規メンバー」を外すかも選べる。理由はログに残る |

## パネルの自動更新

Bot を更新してパネルの見た目やボタンが変わったときは、**次の Bot の起動時に、設置済みのパネルが自動で新しい内容に書き換わる**。
メッセージを消して送り直すのではなく編集するので、パネルの場所・並び順はそのままで、通知も飛ばない。

- 設置したパネルの場所は DB（`panels` テーブル）に覚えておく。前回から中身が変わったパネルだけ編集する
- 進行度・コンテンツパネルのボタンは、そのときサーバーにあるロールに合わせる（ロールが全部消されているときは、壊さないよう前のまま）
- パネルを削除したら、次の起動時に覚えていた場所も消す。いらなくなったパネルは普通にメッセージを削除すればよい
- この仕組みより前に設置したパネルは、覚えているパネルが1つもないときに、Bot が読めるチャンネルの最近 100 件から探して覚える
- 書き換えたパネルは「ログ」に ⚙️ で残る（パネルへのリンク付き）

## 抜けた人の後片付け

メンバーがサーバーを抜けたら、`プロフ` の投稿を削除し、DB のプロフィールを「退出済み」にする。
審査中の申請があれば無効にして、`確認` の申請メッセージに書き足す。結果は退出のログに残る。

- 退出済みのプロフィールは検索などには出ない。データは残すので、戻ってきて申請し直すときは前の内容が入った状態から始まる

## 行動ログ

**「ログ」という名前のテキストチャンネル** にログを送り、同じ内容を DB にも残す（あとから [ログ検索](#ログ検索) で探せる）。
ログはサイレント（通知なし）で、どれも次の形の埋め込みになる。

- タイトル: 何のログか（「メンバー参加」「ロール変更」「メッセージ削除」など）。種類ごとに色が違う
- 本文: 何があったかの一文と、その下に1行ずつの情報（`👤 ユーザー: @名前（ユーザー名）`、`🆔 ユーザーID: …`、`📢 チャンネル: …`、`🕒 アカウント作成: …` など）
  - 別の人が対象のときは `🛠️ 実行者` と `👤 対象`・`🆔 対象のID`
  - 抜けた人はメンションが「@不明」と表示されるので、ユーザー名とIDでも分かるようにしている
- 項目: 長いもの（メッセージの内容・編集前と編集後・添付ファイル・持っていたロール・理由・リンクなど）
- 上に実行した人の名前とアイコン、右に対象の人のアイコン、日時

「ログ」チャンネルは、Bot の起動時（と新しいサーバーに招待されたとき）になければ自動で作る。
作るときは @everyone からは見えなくし、「管理者」ロールと Bot だけが見られるようにする（サーバーのオーナーと管理者権限を持つ人は常に見える）。
作れなかった場合（Bot にチャンネルの管理権限がないなど）は、ログを送らないだけで Bot は動く（DB には残す）。

### Bot の機能のログ

| ログ | いつ | 詳しい内容 |
| --- | --- | --- |
| メンバー参加 | サーバーに参加した | アカウント作成日（7日以内なら ⚠）、**使われた招待リンク**（作った人・何回目か）、メンバー数 |
| メンバー退出 | サーバーから抜けた | 参加日、在籍期間、持っていたロール、メンバー数、後片付けの結果。**キック・BAN なら「メンバー退出（キック）」として、実行者と理由** |
| 進行度の変更 | 進行度ロールを付けた・変えた | 変更前・変更後 |
| コンテンツロールの変更 | コンテンツロールを付け外しした | 変更後のコンテンツロール |
| プロフィール申請 | プロフィールを申請した | 新規 / 登録内容の変更、キャラクター名・ワールド・活動時間・ジョブ・ひとこと、無効にした前の申請、申請へのリンク |
| 申請の許可 | 管理者が申請を許可した | 申請者、プロフィールの内容、「正規メンバー」ロールの結果、DM を送れたか、プロフィール・申請へのリンク |
| 申請の拒否・キック（審査）・BAN（審査） | 管理者が申請を拒否した、申請者をキック・BANした | 申請者、キャラクター名、理由、DM を送れたか、申請へのリンク |
| プロフィール登録（管理者） | 管理パネルから登録した | 登録した人、プロフィールの内容、プロフィールへのリンク |
| プロフィール変更 | 設定パネルで変更した | 変わった項目ごとの変更前・変更後、プロフィールへのリンク |
| プロフィール削除 | 管理パネルから削除した | 削除した人、プロフィールの内容、理由、後片付けの結果 |
| VC入室・VC退出・VC移動 | VCに入った・抜けた・移った（Botは除く） | チャンネル、滞在時間、その時点の人数 |
| VCステータス | VCステータスを設定した・消した（Botのボタンから） | チャンネル、ステータス |
| VC通知の設定 | VC通知・自分が入ったときのお知らせをオン・オフにした | 変更後の設定 |
| メッセージ削除 | メッセージが削除された | 内容、添付ファイル名、チャンネル、送信日時、メッセージID。まとめて削除されたときは件数と、誰のメッセージが何件か |
| メッセージ編集 | メッセージが編集された | 編集前・編集後、チャンネル、送信日時、メッセージへのリンク。リンクのプレビューが付いただけ・ピン留めなど、本文が変わっていないものは残さない |
| パネル設置 | 管理者がパネルを設置した | チャンネル、パネルへのリンク |
| パーティ募集 | 募集が作られた・中止された | コンテンツ、開始日時、募集の形、参加していた人、募集へのリンク |
| 招待リンク作成・削除 | 招待リンクが作られた・なくなった（期限切れ・使い切りも含む） | リンク、作った人、有効期限、使える回数、使われた回数 |
| 管理コマンド実行・失敗 | 管理者がコマンドを使った | コマンド、オプション、失敗したときはエラー |
| 権限拒否 | 管理者でない人が管理者用のコマンド・ボタンを使おうとした | 何をしようとしたか（同じ人の同じ操作は1分に1回まで） |
| ログ検索 | 管理パネルからログを探した | 探した条件、一覧か CSV か |
| Bot | 「管理者」「VC」ロール・「ログ」チャンネルを自動で作った、パネルを書き換えた、週の結果を投稿した | 書き換えたパネルへのリンクなど |

### 管理操作のログ（Discord の監査ログから）

Discord の画面で直接行われた操作も、監査ログから **誰がやったか** 付きで残す（Bot 自身の操作は、上の Bot の機能のログに詳しく残すので除く）。

| ログ | 詳しい内容 |
| --- | --- |
| ロール変更 | 付与・剥奪したロール（ほかの Bot が自動で付け外ししたもの、例えばVCに入ったら付くロールは数が多いので除く） |
| ニックネーム変更 | 変更前・変更後（本人が変えたものも） |
| タイムアウト・タイムアウト解除 | 解除される日時、理由 |
| キック・BAN・BAN解除・メンバーの整理 | 理由 |
| サーバーミュート・スピーカーミュート、VC移動・VC切断（管理者） | 人数・チャンネル |
| メッセージ削除（管理者）・メッセージ一括削除（管理者） | 誰のメッセージか、チャンネル、件数 |
| チャンネル作成・削除・設定変更、チャンネル権限変更 | 変わった設定（並び替えだけのものは除く）、増えた・減った権限 |
| ロール作成・削除・設定変更、サーバー設定変更、Bot追加 | 変わった設定、増えた・減った権限 |

### 記録の残し方

- **発言**: 全部 DB の `message_logs` に残す（Bot・Webhook と「ログ」チャンネルは除く）。Bot を再起動したあとに消された・編集されたメッセージでも、内容と添付ファイル名が分かる。**30日で自動で消す**
- **VCの出入り**: DB の `voice_sessions` に残す。Bot を再起動している間もそのまま入っていた人の滞在時間は正しく出る。止まっている間に入った人は「〇分以上（目安）」になる
- **行動ログ**: DB の `activity_logs` に残す
- VCの出入りと行動ログは **365日** で自動で消す（起動時と、そのあと6時間ごとに片付ける）
- 添付ファイルは削除と同時に Discord から消えるので、ファイル名だけ残す

### ログ検索

管理パネルの「🔎 ログ検索」か `/ログ検索`（英語クライアントでは `/log-search`）で、残しておいたものを探せる（管理者だけ・結果は自分にだけ表示）。

- 条件: 種類（すべて / 行動ログ / 発言 / VCの出入り）、メンバー（その人が実行した・対象になったもの）、期間、キーワード（見出し・内容。VCの出入りには使わない）
- 一覧: 新しい順に15件
- CSV: 10,000件まで。Excel で文字化けしないようにしてあり、メンションやチャンネルは名前に置き換える
- 管理パネルから探したことは「ログ検索」としてログに残る（`/ログ検索` は「管理コマンド実行」として残る）

### 必要な設定・権限

Developer Portal の 対象アプリ > **Bot** > **Privileged Gateway Intents** で、次の2つをオンにしておく必要がある
（オフのままだと Bot がログインできない）。

- **Server Members Intent**（参加・退出のログ）
- **Message Content Intent**（削除・編集のログでメッセージの内容を読むため）

Bot のロールには、次の権限も要る（管理者権限があれば全部含まれる）。

- **監査ログを表示**（管理操作のログ、退出がキック・BAN だったか）
- **サーバーの管理**（どの招待リンクで入ったか。ないと「不明」になる）

## 通話の開始・終了のお知らせ

**「通知」という名前のテキストチャンネル** に、通話の開始と終了を流す。

| | タイミング | 内容 |
| --- | --- | --- |
| 🔊 開始 | 誰もいないVCに最初の1人が入ったとき | @VC と始めた人へのメンション＋埋め込み（VC名、「通話に参加」ボタン）。通知は「VC」ロールの人にだけ届く。始めた人が設定で「知らせない」にしていたら、@VC なしのサイレント |
| 🔇 終了 | VCに誰もいなくなったとき | 埋め込みのみ（VC名、参加した人、最後に通話時間）。サイレント |

- Bot は人数に数えない（読み上げBotだけが残っていても、人がいなくなれば終了）
- 開始は、入ってから5秒待ってまだ誰かいるときだけ流す（自動でVCを作るBotの入口チャンネルを通っただけ、などを除くため）
- 終了は、誰もいなくなってから30秒待って流す。その間に誰かが戻ってきたら同じ通話の続きとして扱う（回線落ちで「終了→開始」が流れないように）。通話時間は誰もいなくなった時点までで計算する
- 終了は、開始を流した通話だけ流す。Bot の再起動前から続いていた通話は、開始・終了とも流さない
- AFKチャンネルは対象外
- 「通知」チャンネルを見られる人が見られないVC（管理者用の非公開VCなど）は、存在が伝わらないよう流さない
- 「通知」チャンネルがなければ何もしない

### 「VC」ロール（VC通知）

開始のお知らせで通知を受け取りたい人には「VC」ロールを付ける。付け外しは、プロフィール登録の最後の手順か、設定パネルの「🔔 VC通知」でできる。

- 「VC」ロールは Bot の起動時（と新しいサーバーに招待されたとき）になければ自動で作る（権限・色なし。メンバー同士で鳴らし合わないよう、誰でもメンションできる設定にはしない）
- Bot がこのロールでメンションするには、Bot に「@everyone、@here、すべてのロールにメンション」の権限（または管理者権限）が必要。
  ない場合は、サーバー設定 > ロール > VC で「誰でも@mentionを許可」をオンにする（オフで権限もないと、メンションは表示されるが通知が届かない。Bot のコンソールに警告が出る）
- 始めた人へのメンションでは通知を飛ばさない（始めた人が「VC」ロールを持っていると、@VC の通知は本人にも届く）
- 「VC」ロールを削除すると、登録の手順から VC通知 が消え、お知らせも @VC なしになる（次の Bot の起動時にまた作られる）

## VCステータス

誰もいないVCに最初の1人が入ると（5秒待ってまだいれば）、**そのVCのチャット**に「📝 VCステータス」のメッセージをサイレントで出す。
VCステータスは、Discord でVCの名前の下に表示される「何をしているか」の一言。

| ボタン | 動き |
| --- | --- |
| ✏️ ステータスを設定 | 入力した一言（100文字まで）をVCのステータスにする。今のステータスが入った状態で開く |
| 🧹 消す | ステータスを消す |

- 押せるのは、そのVCに入っている人と管理者だけ（サーバーの「VCステータスを設定」権限がない人は使えない）
- メッセージには今のステータスと、最後に変えた人が出る。変えたことは「ログ」に残る
- Bot が代わりに設定するので、Bot に **「チャンネルの管理」権限**（または管理者権限）が要る
- Discord は誰もいなくなるとステータスを消すので、次の通話では新しいメッセージを出し、前のメッセージは消す
- AFKチャンネルと Bot の入室では出さない

## VC入室のお知らせ

メンバーがVCに入る（別のVCからの移動も含む）と、そのVCのテキストチャットにお知らせを送る。

- プロフィール登録済みなら、プロフに投稿されるものと同じ埋め込みを送る。未登録なら「〇〇 が入室しました」だけ
- 設定パネルの「🔔 VC通知」で「出さない」にした人の分は送らない
- Botの入室、ミュートの切り替え、退出では送らない
- 回線落ちなどで同じVCに入り直したときは、1分間は送らない
- Bot がそのVCのチャットに書き込めない設定（チャンネルの権限）なら何もしない
